Three ways to hide the group panel

The group column is a fixed 140 px inside the 350 px layer panel and has no way to get out of the way. Each mock below is clickable. When groups are hidden the layer panel shrinks and the canvas takes the room; the outer splitter still lets you drag the layer list wider.

A

Toolbar toggle, next to Tabs

A checkable Groups button in the main toolbar, styled and wired exactly like the existing Tabs toggle: checked means shown, a black inset border marks the checked state. Global and explicit.

Click the Groups button in the toolbar.

For

  • Zero learning cost: it is the Tabs button again, one slot over.
  • Always visible, labeled, and persistable like Tabs (settings file line, restored on launch).
  • Smallest code change: one button, one handler, one width constant.

Against

  • The toolbar is already fighting for room; a 17th button squeezes German and Spanish labels further.
  • The control sits far from the thing it controls, on the other side of the window.
B

Collapse grip on the panel edge

A 14 px grip between the layer list and the group column, with a chevron. Click it and the group column folds into the grip, which stays put as the handle to reopen it, carrying a small GROUPS label and a count so the feature never disappears from view.

Click the grip between the layer list and the group column.

For

  • The control lives on the thing it hides, so cause and effect are obvious.
  • No toolbar cost at all; the grip reuses the inner splitter that already exists between the two columns.
  • A pattern people know from Photoshop and VS Code side panels.
  • Collapsed, the label and count keep groups discoverable.

Against

  • Smaller click target than a toolbar button.
  • Needs mirroring for Hebrew, where the grip and chevron sit on the other side.
  • Hidden state keeps 14 px, so the canvas gains 126 px rather than 140.
C

Groups as a section under the layer list

Drop the side-by-side layout. The group tree becomes a collapsible Groups section stacked under the layer list, with a compact Create button in its header. Collapsed, only the 26 px header remains. Because there is no second column, the layer panel sits at 210 px even with groups open, so the canvas keeps the extra 140 px all the time.

Click the Groups header inside the layer panel.

For

  • Canvas gains 140 px permanently, shown or hidden.
  • One narrow panel instead of two columns; group names get the full 200 px of width.
  • The header doubles as the Create button's home, so nothing is lost when collapsed.

Against

  • The group tree now competes with the layer list for vertical space in projects with many layers.
  • Changes a layout users already know.

Recommendation. B fits the current code best: it costs no toolbar room, sits where the user is looking, and reuses the splitter that already separates the two columns. C gives the best end result if a layout change is on the table. A is the fallback if you want it done in an hour, and A and B can also coexist, with the toolbar button driving the same grip.
Shared by every option
  • Remembered between sessions. One line in user_settings.txt, GroupPanelVisible: true, written with the same read-modify-write the Tabs edge position uses, so the settings dialog's own lines are untouched.
  • Keyboard shortcut. Ctrl+G (⌘G on macOS) toggles it from anywhere; the app has no shortcuts today, so this would be the first.
  • Translations. One new key in all seven languages, plus a tooltip variant, following the tabs / toggle_shadow keys.
  • Compact screens. The narrow-window path that slims the layer panel keeps working: hidden state simply removes the group column from that arithmetic.
